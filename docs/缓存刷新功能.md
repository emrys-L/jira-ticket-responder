# 缓存刷新功能

## 📋 问题背景

**原问题**：EEESC-376 显示停滞 21 天，但实际 Jira 上最后评论是 4-29（8 天）

**根本原因**：
- jira-ticket-responder 依赖本地缓存 `data/raw_issues/`
- 缓存不会自动更新
- 分析基于过期数据

## ✅ 解决方案

### 新增功能

1. **自动刷新缓存** - 分析前自动从 Jira API 获取最新数据
2. **智能刷新策略** - 只刷新超过 7 天未更新的工单
3. **独立刷新工具** - 可手动刷新指定工单或全部工单

### 修改内容

1. **新增 `scripts/cache_refresh.py`** - 缓存刷新模块
2. **修改 `scripts/batch_analyze_all.py`** - 集成自动刷新
3. **新增 `config.py`** - Jira API 配置

## 🚀 使用方法

### 方式 1：自动刷新（推荐）

运行批量分析时自动刷新缓存：

```bash
cd /home/syrme/jira-ticket-responder
python3 scripts/batch_analyze_all.py
```

**刷新逻辑**：
- ✅ 只刷新待分析的工单（排除今天已回复）
- ✅ 只刷新超过 7 天未更新的缓存
- ✅ 显示刷新进度和结果

### 方式 2：手动刷新

#### 刷新所有工单

```bash
python3 scripts/cache_refresh.py --all
```

#### 刷新指定工单

```bash
python3 scripts/cache_refresh.py --issue EEESC-376
```

#### 强制刷新（忽略缓存年龄）

```bash
python3 scripts/cache_refresh.py --all --force
```

## 📊 刷新策略

### 默认策略（7 天规则）

- 缓存 < 7 天：跳过（使用本地缓存）
- 缓存 ≥ 7 天：刷新（从 Jira API 获取）

**优点**：
- ✅ 减少 API 调用
- ✅ 加快分析速度
- ✅ 数据保持相对新鲜

### 强制刷新

使用 `--force` 参数忽略缓存年龄，总是从 Jira API 获取最新数据。

**适用场景**：
- 工单刚刚更新
- 需要最新数据
- 调试问题

## 🐛 故障排查

### 刷新失败

**错误**：`404 Issue does not exist`

**原因**：工单已删除或无权限

**解决**：检查工单号是否正确，或联系管理员

### 刷新慢

**原因**：网络延迟或 Jira API 限流

**解决**：
1. 检查网络连接
2. 减少并发数量
3. 避开高峰期
